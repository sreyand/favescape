# Favescape

A personal music player and visual map of the songs you love. Import local audio, rate how it fits your moods, explore the connections, and build a TastePlay listening session from your own library.

The design follows the original TasteMap mockup: warm cream, cobalt blue, tomato red, expressive retro typography, and a spacious song map. The reference is saved in `docs/design/tastemap-reference.png`.

## Start on Windows

Install **Node.js 22.12+** and **Python 3.12+**. Python 3.12 was used for the initial implementation. From the repository root:

```powershell
.\scripts\setup.ps1
npm run dev
```

If you have several Python installations, provide the executable explicitly:

```powershell
.\scripts\setup.ps1 -PythonExecutable "C:\Path\To\Python312\python.exe"
```

The setup script creates a project-local `.venv`, installs Python and JavaScript dependencies locally, and generates the original demo WAV files. It does not change execution policy, require administrator privileges, or install packages globally. If your PowerShell policy blocks script execution, run these equivalent commands individually:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd install
.\.venv\Scripts\python.exe scripts\generate_demo.py
npm.cmd run dev
```

Open **http://127.0.0.1:5173**. `npm run dev` starts three local processes: the FastAPI server on port 8765, the feature-analysis worker, and Vite on port 5173. Stop the development command with Ctrl+C. Both servers bind to loopback. The browser communicates with the API through Vite's `/api` proxy.

## What works

- Local audio import, metadata reading, duplicate detection, and optional embedded cover art.
- A persistent player with seeking, volume, previous/next, and an editable queue.
- Separate enjoyment scores and 1–5 mood-fit ratings, custom moods, notes, and rating history.
- A personal mood map, a measured-feature sound view, and a metric view, with selection, filtering, search, pan/zoom, and saved manual positions.
- Genre tags, named collections, and intentional connections between tracks.
- TastePlay sessions selected from explicit mood fit, enjoyment, and artist variety, with editable queues and a path over the existing map.
- Explicit “great fit” / “wrong mood” session feedback, recorded separately from ratings. Skipping does not create a dislike.
- Versioned map export/import and relinking of missing audio.
- Durable background measurement of tempo, spectral brightness, and RMS amplitude.

TastePlay is an explainable scoring system in this version. It selects playable tracks rated at least 3/5 for the chosen mood, favors enjoyment when available, avoids duplicate tracks, and softly penalizes repeated artists. It uses whole songs, reports actual duration, and explains when there are too few matching tracks.

## Your music and local data

Start with lawfully obtained local files, such as authorized DRM-free purchases or artist-provided downloads. Subscription offline downloads do not necessarily provide ordinary audio files that another app can read. Import currently accepts MP3, WAV, FLAC, M4A/AAC, OGG, OPUS, and AIFF; browser playback and analysis-decoder support vary. An analysis failure does not disable an otherwise playable file.

The SQLite database, imported audio, extracted cover art, generated demos, and analysis jobs live in the ignored `.data/` directory. Audio analysis happens locally, with no external model or audio service. Metadata, ratings, queues, and sessions survive a restart; playback does not automatically begin when the app reopens.

Map exports contain metadata, ratings and their histories, positions, connections, collections, sessions, and explicit feedback. They contain no raw audio or local filesystem paths. Importing the exact matching audio file relinks by SHA-256. Entries whose files are missing remain visible but cannot play until relinked.

Acquiring a file, privately analyzing it, redistributing audio, and training a shared model are separate questions. Do not assume a purchase grants unrestricted reuse, or that every private analysis necessarily requires explicit artist permission. Any public catalog, streaming integration, or shared training feature needs its own source and use assessment.

## Demo collection

The first empty library is seeded with 12 fictional tracks and illustrative mood/enjoyment ratings. Their sleeves are original SVG artwork. Their audio is original procedural synthesis generated by `scripts/generate_demo.py`: no commercial recordings, samples, or downloads are included. See `docs/demo-assets.md` for provenance.

```powershell
.\.venv\Scripts\python.exe scripts\generate_demo.py
```

Generation is idempotent; existing demo audio is retained. `--force` regenerates these demo files. The app does not repeatedly add demo tracks to an existing library.

## Audio measurements and map meaning

The `spectral-onset-v1` worker uses numpy, scipy, and soundfile. It analyzes entire short clips or three 15-second windows spread across a longer track. Tempo is an onset-autocorrelation estimate and can have half/double-time errors. Spectral centroid is a brightness proxy in Hz. RMS is linear waveform amplitude, not perceived loudness or emotional energy.

The mood map is based on personal ratings. Proximity on that map does not automatically mean sonic similarity. The sound view uses a small measured-feature baseline; it is not a validated judgment of musical or emotional similarity. Metric axes are labeled with the actual measurements used. No custom ML model is trained in V1.

## Project structure

```text
apps/web/                 React/TypeScript interface, map, player, styles
backend/app/             FastAPI routes, typed schemas, SQLite persistence
backend/app/migrations/  Versioned SQLite migrations
backend/analysis/        Measured audio feature extraction
backend/worker/          Recoverable single-worker job loop
fixtures/                Synthetic demo metadata and ratings
scripts/                 Windows setup, local development, demo generation
docs/                    Design reference, API contract, progress and provenance
.data/                   Ignored personal library and generated audio
```

## Useful commands

```powershell
npm run typecheck
npm run build
.\.venv\Scripts\python.exe -m backend.worker --once
```

The build command typechecks and builds the frontend. The worker's `--once` mode drains currently queued analysis and exits. See `backend/README.md` for individual API/worker commands and `docs/api-contract.md` for the API contract. Dependency versions are captured in `package-lock.json` and `backend/requirements.txt`.

## Validation and next steps

The backend was checked with an isolated real HTTP flow covering WAV import, audio byte ranges, duplicate reuse, ratings and history, deterministic TastePlay, exclusion of unknown/low mood fit, explicit feedback, stale-position revision handling, export/import, missing references, queue restoration, corrupt-file cleanup, worker recovery, and measured features. This did not modify the preview library. Frontend and browser validation status is recorded in `docs/progress.md`.

Future experiments include pretrained audio embeddings, a small mood-fit classifier, a learned TastePlay ranker, multi-mood journeys, and deliberate map comparison/sharing. These are deferred until the local playback, rating, and visualization experience has been evaluated. Broad streaming catalog access is not solved by the current local-file workflow.
